# design-sync notes — core-platform-site

## Why this repo is scoped down to three components

`core-platform-site` is the THRIVE portal application itself (Next.js on
Cloudflare Workers), not a design-system component library. It has no
`main`/`module`/`exports`/`types` in `package.json`, no `dist/` component
build, no Storybook. Almost everything under `app/` is a Next.js page or a
component tightly coupled to server-only code (`drizzle-orm`, `getDb`,
session/auth) — see `CLAUDE.md`'s rule that authorization must never move to
the client. Bundling that surface for a client-side preview would either fail
outright or risk pulling auth-adjacent server code into an artifact uploaded
to claude.ai/design.

The user chose (2026-08-19) to scope this sync down to the only genuinely
standalone, presentational, client-safe pieces found in the repo: the brand
glyphs.

- `app/thrive-mark.tsx` — `ThriveMark`
- `app/rank-medallion.tsx` — `RankMedallion`, `METAL_FOR_ROLE`
- `app/key-glyph.tsx` — `KeyGlyph`

Each is pure inline SVG with zero imports beyond React — no data fetching,
no auth, no navigation.

## The hand-built package boundary

Since there's no real npm package here, `.design-sync/pkg/` is a **hand-authored**
synthetic package boundary (not generated by the converter): a `package.json`
naming it `thrive-brand-marks`, and `index.tsx`, a barrel that re-exports only
the three components above by relative import. `cfg.entry` points straight at
that barrel (`resolveDistEntry`'s override path — bypasses all dist/src
discovery), so esbuild's bundle graph is exactly those three files' content;
nothing else in `app/` is ever visited or bundled.

`cfg.componentSrcMap` pins each component's real source path (`../../app/*.tsx`,
relative to `.design-sync/pkg/`) purely for docs/JSDoc enrichment (each file
has good header JSDoc) — it does not affect what gets bundled.

No `cfg.srcDir` is set — `.design-sync/pkg/` has no `src/`/`lib`/`components`
subdirectory, so the converter's directory-walk synth-entry path (which would
otherwise scan an entire source tree for PascalCase exports) never engages.
**Do not set `cfg.srcDir` to `app/`** — that would make the converter try to
bundle every page and server-coupled component in the app.

## Re-sync risks

- If the three glyph files move or get renamed, update both `.design-sync/pkg/index.tsx`'s
  imports and `cfg.componentSrcMap` together.
- If a future sync wants to add more components from this repo, each new
  candidate needs the same manual safety check this run did: confirm zero
  imports of server-only modules (`drizzle-orm`, `next/headers`, `getDb`,
  anything under `app/portal/access.ts`) before adding it to the barrel.
- Adding a component that turns out to transitively import server code would
  make esbuild either fail the build (most likely) or, worse, silently bundle
  it — always check the build log's import list, not just the exit code.
