## 3. Color Contrast Analysis

### 3.1 Palette Reference

| Name | Hex | Role in portraits |
|------|------|-------------------|
| Violet | `#6d42e5` | Primary accent for Portraits 01, 04, 06 |
| Coral | `#ff7062` | Primary accent for Portraits 02, 07 |
| Gold | `#f4bd4f` | Primary accent for Portraits 05, 10 |
| Mint | `#58c7a2` | Primary accent for Portraits 08, 09 |
| Blue | `#3d7edb` | Primary accent for Portraits 03, 06, 09, 10 |
| Ink | `#16142b` | Shared background for all portraits |
| Paper | `#fffaf2` | THRIVE site light background |

### 3.2 Contrast Ratios Against Portrait Background (Ink `#16142b`)

| Color | Ratio | AA Normal (4.5:1) | AA Large (3:1) | AAA Normal (7:1) |
|-------|-------|--------------------|-----------------|-------------------|
| Violet `#6d42e5` | 3.05:1 | FAIL | PASS | FAIL |
| Coral `#ff7062` | 6.63:1 | PASS | PASS | FAIL |
| Gold `#f4bd4f` | 10.47:1 | PASS | PASS | PASS |
| Mint `#58c7a2` | 8.64:1 | PASS | PASS | PASS |
| Blue `#3d7edb` | 4.45:1 | FAIL | PASS | FAIL |

**Finding:** Violet and Blue do not meet AA normal-text contrast against the ink background. This is acceptable for the portraits themselves (which are decorative images, not text), but any text overlaid on these colors against ink must use a different approach. See recommendations below.

### 3.3 Portrait Colors Against Light Backgrounds

| Color | vs Paper `#fffaf2` | vs White `#ffffff` |
|-------|---------------------|--------------------|
| Violet `#6d42e5` | 5.67:1 (AA PASS) | 5.90:1 (AA PASS) |
| Coral `#ff7062` | 2.61:1 (FAIL) | 2.71:1 (FAIL) |
| Gold `#f4bd4f` | 1.65:1 (FAIL) | 1.72:1 (FAIL) |
| Mint `#58c7a2` | 2.00:1 (FAIL) | 2.08:1 (FAIL) |
| Blue `#3d7edb` | 3.88:1 (AA-large only) | 4.03:1 (AA-large only) |

**Finding:** Only violet provides sufficient contrast for text use against light backgrounds. Coral, gold, and mint all fail even AA large text requirements on white or paper.

### 3.4 Text Overlay Recommendations

**Safe combinations for text overlaid on or near portraits:**

| Text color | Background | Ratio | Verdict |
|------------|------------|-------|---------|
| White `#fff` on Violet `#6d42e5` | -- | 5.90:1 | AA PASS for all text sizes |
| Ink `#16142b` on Coral `#ff7062` | -- | 6.63:1 | AA PASS for all text sizes |
| Ink `#16142b` on Gold `#f4bd4f` | -- | 10.47:1 | AAA PASS |
| Ink `#16142b` on Mint `#58c7a2` | -- | 8.64:1 | AAA PASS |
| White `#fff` on Blue `#3d7edb` | -- | 4.03:1 | AA large text only |
| Ink `#16142b` on Blue `#3d7edb` | -- | 4.45:1 | AA large text only |

**Guidance:**
- For names or labels placed on or near coral, gold, and mint portrait accents, use ink-dark text (`#16142b` or darker).
- For names or labels on violet portrait accents, use white text.
- For blue portrait accents, neither white nor ink meets AA for normal-size text. Use large/bold text only, or place the label outside the blue region on a contrasting ground.
- Never place coral, gold, or mint text on white or paper backgrounds for any functional content.

### 3.5 Colorblind-Safe Usage Guidance

**Luminance values** (relative luminance, 0-1 scale):

| Color | Luminance |
|-------|-----------|
| Violet | 0.1280 |
| Blue | 0.2103 |
| Coral | 0.3373 |
| Mint | 0.4553 |
| Gold | 0.5619 |

**Pairwise contrast between portrait accent colors:**

| Pair | Ratio |
|------|-------|
| Violet vs Gold | 3.44:1 |
| Violet vs Mint | 2.84:1 |
| Gold vs Blue | 2.35:1 |
| Violet vs Coral | 2.18:1 |
| Mint vs Blue | 1.94:1 |
| Coral vs Gold | 1.58:1 |
| Coral vs Blue | 1.49:1 |
| Violet vs Blue | 1.46:1 |
| Coral vs Mint | 1.30:1 |
| Gold vs Mint | 1.21:1 |

**Analysis by color vision deficiency type:**

**Protanopia / Deuteranopia (red-green):**
- Coral and mint are the highest-risk pair (1.30:1 contrast, and both shift toward brownish-yellow under red-green simulation). In a grid or list, these two portraits may appear nearly identical in hue.
- Gold and coral also risk conflation (1.58:1).
- Recommendation: When portraits must be distinguishable by color alone (e.g., a legend mapping colors to roles), add a secondary differentiator such as shape, pattern, icon, or text label. Never rely solely on accent color to communicate which portrait represents which role.

**Tritanopia (blue-yellow):**
- Violet and blue are the highest-risk pair (1.46:1 contrast). Both shift toward a similar cyan-teal under tritanopia simulation.
- Gold and mint also converge (1.21:1), both trending toward pinkish tones.
- Same recommendation: always provide a non-color differentiator.

**Universal recommendation:**
- In any UI where the user must distinguish between portrait roles (member directory, role assignment, navigation), pair each portrait with its role name as visible text.
- If portraits are used as color-coded indicators (e.g., status dots), this palette is not suitable without added shape or pattern differentiation.
- The luminance spread is reasonable (0.13 to 0.56), so lightness alone provides some differentiation even when chroma is lost, but the middle range (coral 0.34, mint 0.46) is too close for reliable discrimination.

## 4. Usage Guidelines

### 4.1 Minimum Display Size

| Context | Minimum size | Notes |
|---------|-------------|-------|
| Profile avatar (nav bar, comment thread) | 32x32 px | At this size the portrait functions as a color badge more than a readable image. Alt text is essential. |
| Profile card / directory listing | 48x48 px | Silhouette becomes recognizable. |
| Full portrait display (profile page) | 128x128 px | Recommended minimum for the portrait to be meaningfully "seen." |
| Contact sheet (all 10) | 640px total width (64px per portrait) | Each portrait must be at least 48px wide for the grid to be useful. |
| Hero / banner use | 1200px wide | Individual portraits within the banner should be at least 80px wide. |
| Print | 1 inch / 2.5 cm minimum per portrait | At 300 DPI, source files should be at least 300x300 px for print use. |

### 4.2 Alt Text vs Decorative

**Use descriptive alt text when:**
- The portrait identifies a specific person or role (avatar next to a name, profile card, member directory).
- The portrait is the primary content of the view (standalone portrait page, enlarged lightbox).
- The portrait links to a profile or action (clickable avatar).
- The collection is presented as editorial content (the article "Ten Agents, Ten Portraits," a gallery page).

**Use `role="presentation"` or `alt=""` (decorative) when:**
- The portrait is purely decorative background (e.g., repeated watermark pattern behind other content).
- The same information is already conveyed by adjacent visible text (e.g., the role name and description appear in text next to the portrait, and the portrait adds no unique information).
- The portrait is used as a CSS background-image in a container that has its own accessible label.

**Never omit the `alt` attribute entirely.** An absent `alt` attribute causes screen readers to announce the filename, which is worse than an empty `alt=""`.

### 4.3 Context-Specific Guidance

**Email:**
- Use inline `alt` text on every `<img>` tag. Many email clients block images by default; the alt text is often the only thing the recipient sees.
- Keep alt text under 125 characters for email (some clients truncate).
- Example: `alt="Mission Keeper -- abstract violet portrait"`
- Do not rely on the portrait to convey critical information. Always include the role name in body text.
- For the contact sheet in email, use: `alt="Ten THRIVE portraits: Mission Keeper, Originality Scout, World Builder, Art Director, Trait Architect, Prompt Engineer, Image Maker, Collection Curator, Quality Guardian, Release Archivist"`

**Social media:**
- Twitter/X: Alt text field supports 1000 characters. Use the full descriptive alt text plus extended description.
- LinkedIn, Facebook: Use the image description field when posting. Include "AI-made" disclosure.
- Instagram: Use the alt text field under Advanced Settings. Keep it under 200 characters.
- Always include "AI-made" or "AI-assisted" in the post text. Some platforms are beginning to require AI-generated content disclosure.

**Print:**
- Alt text does not apply in print, but companion text descriptions should appear in captions or an appendix for accessibility in print-plus-digital formats (e.g., PDF).
- For PDF output, set each portrait as a figure with alt text using the PDF/UA tagging structure (`/Alt` in the image dictionary).
- Ensure the PDF is tagged (not just visually formatted) so screen readers can traverse it.

### 4.4 Animation / Motion Considerations

If any portraits have animated variants (e.g., subtle shimmer, color shift, entrance animation):

- Respect `prefers-reduced-motion: reduce`. Under this setting, suppress all animation and display the static portrait.
- Never auto-play animation that lasts longer than 5 seconds without a mechanism to pause, stop, or hide it (WCAG 2.2.2).
- Do not use flashing or strobing effects. The palette includes high-chroma colors (coral, gold) that could produce dangerous flash rates if rapidly alternated.
- If animation conveys information (e.g., a pulsing border indicates online status), provide a non-animated text equivalent.

```css
@media (prefers-reduced-motion: reduce) {
  .portrait-animated {
    animation: none !important;
    transition: none !important;
  }
}
```

## 5. ARIA Patterns

### 5.1 Avatar in Navigation Bar

```html
<nav aria-label="Main navigation">
  <a href="/portal/profile" class="nav-avatar">
    <img
      src="/portraits/mission-keeper.webp"
      alt="Mission Keeper"
      width="32"
      height="32"
      class="avatar-img"
    />
    <span class="nav-username">Shawn M.</span>
  </a>
  <!-- ... other nav items ... -->
</nav>
```

Notes:
- The `alt` is brief because the adjacent visible text provides context.
- If the avatar is the only clickable element (no visible name), the alt must include the destination: `alt="Shawn M. -- go to profile"`.
- Do not use `role="img"` on an `<img>` element; it is redundant.

### 5.2 Profile Card

```html
<article class="profile-card" aria-labelledby="card-name-01">
  <img
    src="/portraits/originality-scout.webp"
    alt="Abstract portrait in coral and mint on dark background"
    width="96"
    height="96"
    class="card-portrait"
    aria-describedby="card-desc-01"
  />
  <h3 id="card-name-01">Jordan Lee</h3>
  <p>Originality Scout</p>
  <p id="card-desc-01" class="sr-only">
    Stylized coral and mint head-and-shoulders silhouette with sweeping
    contours, part of the THRIVE ten-portrait AI-made collection.
  </p>
</article>
```

CSS for the screen-reader-only extended description:

```css
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border: 0;
}
```

### 5.3 Portrait Gallery Grid

```html
<section aria-label="THRIVE portrait collection">
  <h2>Ten Agents, Ten Portraits</h2>
  <ul role="list" class="portrait-grid">
    <li>
      <figure>
        <img
          src="/portraits/01-mission-keeper.webp"
          alt="Portrait 1 of 10: Mission Keeper. Abstract violet silhouette with gold accents on deep ink background."
          width="256"
          height="256"
          loading="lazy"
        />
        <figcaption>01 -- Mission Keeper</figcaption>
      </figure>
    </li>
    <li>
      <figure>
        <img
          src="/portraits/02-originality-scout.webp"
          alt="Portrait 2 of 10: Originality Scout. Abstract coral and mint silhouette on deep ink background."
          width="256"
          height="256"
          loading="lazy"
        />
        <figcaption>02 -- Originality Scout</figcaption>
      </figure>
    </li>
    <!-- ... portraits 03 through 10 follow the same pattern ... -->
  </ul>
</section>
```

Notes:
- Using `<figure>` and `<figcaption>` provides semantic grouping. The `<figcaption>` is the visible label; the `alt` carries the full description for screen readers.
- `role="list"` is explicitly set because some CSS resets (including Safari's treatment of `list-style: none`) strip list semantics.
- `loading="lazy"` is set on all but the first visible row to avoid layout shift above the fold.
- "Portrait N of 10" gives screen reader users positional context within the collection.

### 5.4 Clickable Avatar Leading to Profile

```html
<a href="/portal/members/jordan-lee" class="member-link">
  <img
    src="/portraits/originality-scout.webp"
    alt=""
    width="40"
    height="40"
    class="member-avatar"
    role="presentation"
  />
  <span>Jordan Lee</span>
</a>
```

Notes:
- Here the image is decorative because the link text "Jordan Lee" fully describes the target. The portrait adds visual interest but not information.
- `alt=""` plus `role="presentation"` ensures no screen reader announces it.
- If the image were the ONLY child of the `<a>`, it would need meaningful alt text naming the link destination.

### 5.5 Portrait with Tooltip on Hover

```html
<div class="avatar-wrapper">
  <img
    src="/portraits/03-world-builder.webp"
    alt="World Builder portrait"
    width="48"
    height="48"
    aria-describedby="tooltip-03"
    tabindex="0"
  />
  <div
    id="tooltip-03"
    role="tooltip"
    class="portrait-tooltip"
  >
    World Builder -- Defines the collection's character archetypes and visual lore.
  </div>
</div>
```

Notes:
- `tabindex="0"` makes the image keyboard-focusable so the tooltip is accessible without a mouse.
- The tooltip uses `role="tooltip"` and is linked via `aria-describedby`.
- Show/hide the tooltip on `:hover` and `:focus-within` of the wrapper div. Never rely on hover alone.

### 5.6 Contact Sheet (Composite Image)

When all ten portraits are combined into a single image file:

```html
<figure>
  <img
    src="/portraits/contact-sheet.webp"
    alt="Contact sheet: ten THRIVE portraits arranged in a two-by-five grid. Top row left to right: Mission Keeper (violet), Originality Scout (coral), World Builder (blue), Art Director (violet-coral), Trait Architect (gold). Bottom row: Prompt Engineer (blue-violet), Image Maker (coral-gold), Collection Curator (mint), Quality Guardian (blue-mint), Release Archivist (gold-blue)."
    width="1280"
    height="512"
  />
  <figcaption>
    The complete THRIVE portrait collection. AI-made, 2026.
  </figcaption>

```

Notes:
- For a composite image, the alt text must describe the arrangement and identify each portrait, since individual `<img>` elements are not available.
- If the contact sheet is purely for visual review and the individual portraits are also available as separate images on the page, use `alt=""` on the composite and let the individual images carry the descriptions.

## 6. Implementation Checklist

For any developer integrating these portraits into the THRIVE platform:

- [ ] Every `<img>` tag has an `alt` attribute (never omitted, empty string for decorative use).
- [ ] Role names appear as visible text adjacent to portrait images; color is never the sole differentiator.
- [ ] Text overlaid on portraits meets WCAG AA contrast: ink-dark text on coral/gold/mint, white text on violet, large text only on blue.
- [ ] `prefers-reduced-motion: reduce` is respected for any animated portrait variants.
- [ ] Gallery views use `<figure>`/`<figcaption>` or equivalent semantic markup.
- [ ] Clickable portraits have either meaningful `alt` text or are marked decorative with visible link text providing the accessible name.
- [ ] Contact sheet composite images include a full enumeration of contents in alt text.
- [ ] PDF exports use tagged structure with `/Alt` entries for each portrait.
- [ ] Email templates include alt text under 125 characters per portrait.
- [ ] Social media posts include alt text in platform-specific fields and "AI-made" disclosure in post body.
- [ ] Minimum display sizes are respected: 32px for avatars, 48px for directory listings, 128px for standalone display.
- [ ] The `sr-only` utility class is available in the stylesheet for extended descriptions.

## 7. AI Disclosure Language

Per the collection's own rules ("describe the work accurately as AI-made"), the following disclosure should accompany the portraits wherever they appear in contexts that could imply human authorship:

**Short form (for captions, footers):**
"AI-made portrait. Part of the THRIVE Ten Agents collection."

**Long form (for about pages, documentation, metadata):**
"This portrait was generated using AI image-generation tools as part of the THRIVE platform's Ten Agents, Ten Portraits collection. The creative direction, trait assignment, curation, and quality review were human-led. The collection does not depict real individuals."

This disclosure should be available programmatically (e.g., in image metadata, `aria-describedby` text, or a linked disclosure page) so that assistive technologies can surface it when users inspect the image.
